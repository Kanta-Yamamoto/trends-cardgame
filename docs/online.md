# オンライン対戦

友だちどうしで試す規模を前提にした、いちばん簡単な作り。広げるときの拡張は最後に書く。

## 流れ

対戦のしかたは 2 つ。**ランダムマッチ**（レートの近い人と組む。レーティングが動く）と、**友だちと対戦**（合言葉の部屋。レーティングは動かない）。

1. Google でログインする（`POST /auth/google`）。API は Google の ID トークンを確かめ、ユーザーを `users` に登録して、自前のトークン（30日）を返す
2. 部屋を作る（`POST /matches`、デッキを選ぶ）。6文字の合言葉ができる
3. 合言葉か招待リンク（`/online/合言葉`）を友だちに送る。友だちがデッキを選んで入ると対戦が始まる
4. 操作は Socket.IO でサーバーに送り、サーバーが `applyAction` でルールを判定して、2人に結果を送る
5. 画面を閉じても、同じ部屋を開き直せば続きから遊べる（対戦の状態は `matches.state` に保存）
6. 通信が切れても（リロード・ほかのアプリを開く・「ロビーへ」）、対戦はサーバーで続く。離れた人のターンは 60 秒で終わり、持ち時間が減っていく（使い切ると負け）。離れた人がオンライン対戦のページ（`/online`）を開くと、ランダムマッチ・友だちと対戦の代わりに「対戦が続いています」と「対戦に戻る」だけが出て、押すと同じ部屋に戻る（`GET /me/match`。決着していない自分の対戦のうち、いちばん新しいもの）。ほかの人の招待リンクを開いても同じ案内だけが出る。決着するまで、ほかの部屋を作る・入る・ランダムマッチに並ぶことはできない（サーバーも「対戦中の部屋があります」で断る）。持ち時間の無い古い対戦は数えない
7. 2 人とも抜けたまま（部屋にだれもつないでいない）1 分たったら、決着なしで対戦を閉じる（`matches.status` が `closed`。勝ち負けなし・レーティングは動かない）。リロードやアプリの切り替えで一瞬 2 人とも切れたくらいでは閉じない。CPU は人の数に入れない（人が抜ければ閉じる）。2 人とも抜けているあいだ、ロビーの「対戦が続いています」には閉じるまでの残りを出す（`GET /me/match` の `closesIn`）。閉じた部屋を開くと「この対戦は、2人とも抜けたので閉じました」。だれもつないでいないとタイマーが遅れることがある（Cloud Run の CPU）ので、`GET /me/match` が来たときにも、時間が過ぎていればその場で閉じる。数え始めは、最後の 1 人の接続が切れたとき・ランダムマッチで組んだとき（だれも部屋に来なければ閉じる）・サーバーが起動し直したとき

ランダムマッチは 2〜3 の代わりに、デッキを選んで待ち行列に入る（Socket.IO の `queue`）。組めたらサーバーが部屋を作って 2 人に合言葉を送り（`matched`）、画面はその部屋（`/online/合言葉`）に入る。そこから先は同じ。

## 通信（Socket.IO）

接続するときに `auth.token` にログインのトークンを入れる。

| クライアント → サーバー | 内容 |
|---|---|
| `join` `{ code, deck? }` | 部屋に入る。2人目は `deck` が必要。すでに参加している人は再接続 |
| `action` `{ code, action }` | 操作（`play` / `cast` / `attack` / `endTurn`）。反則なら返事が `{ ok: false, error }` |
| `resign` `{ code }` | 降参 |
| `ready` `{ code, turn }` | 自分のターンが始まった手を見せ終えた。待っている自分の時計を動かしてもらう |
| `queue` `{ deck }` | ランダムマッチの待ち行列に入る（同じ人が並び直したら新しいほうだけ残る） |
| `unqueue` | 待ち行列から出る（接続が切れても出る） |

| サーバー → クライアント | 内容 |
|---|---|
| `match` | 部屋の様子（自分・相手の名前とデッキ、対戦の状態） |
| `update` | 1手分（操作・出来事・操作後の状態・時計） |
| `matched` `{ code }` | ランダムマッチで組めた。その部屋に入る |
| `clock` | 時計だけが変わった（手番の人の `ready` で動き出した） |
| `rated` `{ before, after }` | 決着でレーティングが動いた（ランダムマッチだけ） |

`match` と `update` の `clock` は、見る人を p1 にそろえた残り時間（`ClockView`：時計が動いている人・ターンの残り・両者の持ち時間）。画面は届いた時刻から自分で減らして見せる。

## 持ち時間

- 個人の持ち時間は 1 試合で 10 分（10月25日に 5 分から）。自分のターンのあいだ、最初の 1 秒から減る。使い切ると時間切れで負け（`timeout`。ルールは `packages/game-core/src/clock.ts`）
- 1 ターンは 60 秒まで（10月25日に 30 秒から）。過ぎたらサーバーがターンを終える（差し出しを選ぶ番なら、先に自動で選ぶ）。持ち時間が 60 秒より少なければ、そこまで
- 時計はサーバーが持つ（`matches.clock`）。切れる時刻にタイマーを掛け、過ぎたらサーバーが代わりに操作する。遅れて届いた操作は、先に時間切れを進めてから判定する
- 相手の手番の途中で差し出し（フィクサー）を選ぶ番なら、手番の人の時計は止め、選ぶ人は 15 秒。過ぎたら自動で選ぶ
- 対戦の始めは 5 秒待ってから時計が動く（部屋に入る・オープニングの間）
- そのあと、両者が同時に手札を引き直す（11月1日）。選ぶ時間は 30 秒で、そのあいだ持ち時間は減らない（`ClockView.mulliganLeft`）。画面は 30 秒で、そのとき選んでいるカードを送る。サーバーはそこから 2 秒（通信の遅れ）待ち、まだ選んでいない人は引き直さないことにする。両者が選び終えたら先攻のターンの時計が動く。待機している CPU も自分で選ぶ（`planMulligan`）
- ターンが変わったら、新しい手番の人の時計は、その人の画面が相手の手の演出を見せ終える（`ready`）まで待つ。待つのは 10 秒まで（知らせが来なくても、そこで動き出す）。相手が手を素早く続けたとき、演出を見ているあいだに自分の時間が減らないように（10月28日）
- サーバーが起動し直したら、決着していない対戦のタイマーを掛け直す（だれも戻らない対戦も時間切れで決着し、レーティングが動く）

## レーティングとランキング

- イロレーティング（K=32、1500 から）。勝つ見込み E = 1 / (1 + 10^((相手 − 自分) / 400))、増減は 32 × (1 − E) を丸めた値（勝てば 1 以上）。2 人の増減は同じ幅。`packages/game-core/src/rating.ts`
- 決着を保存する取引の中で両者の値を動かす（`users.rating`・`rated_games`・`wins`、対戦の前後の値は `matches.ratings`）。1 試合で 1 回だけ
- ランダムマッチの組み方：長く待っている人から、組める相手のうちレートがいちばん近い人と。組めるのは差が「200 ＋ 1 秒待つごとに 20」以内（長く待った人に合わせる）。`apps/api/src/matches/matchmaking.ts`
- 待機している CPU：15 秒待っても人と組めなければ、CPU と組む（`matches.kind` は `cpu`）。人どうしを先に組み、残った人だけ CPU に回す。CPU は待ち行列に並ばないので、CPU どうしでは組まない。CPU はサーバーの中で動く（`users` の `cpu:standby`、名前は「CPU」）。自分の番になったら間を置いて、先読みする CPU（`planTurnSearch`）の最初の 1 手を打ち、また考え直す。差し出しを選ぶ番なら自動で選ぶ。デッキは構築済みデッキの 7 つから 1 つ（`packages/cards/src/cpuDecks.ts`）。CPU との対戦ではレーティングは動かない（同じ CPU に勝ち続けてレートを上げられないように）
- ランキング（`GET /rankings`、画面は `/ranking`）：時計の 10 分ごとの区切り（0 分・10 分…）で集計し直し、その間は同じ集計を返す。1 戦以上した人の上位 100 人と、集計の中での自分の順位。自分の今のレートは `GET /me/rating`

## 見せる情報

- どちらの人にも、**自分が p1** になるように入れ替えて送る（画面は CPU 戦と同じ作りのまま使える）。`packages/game-core/src/view.ts`
- 相手の手札、両者の山札の中身、乱数の種は送らない（枚数だけ分かる）。相手が引いたカードの出来事も隠す
- ルールの判定はすべてサーバー。クライアントは見た目だけ

## 届いた手の見せ方（二人が同時に動くときの守り）

10月28日、フレンド対戦で、相手が裏向きのカードの説明を見ている最中に闇堕ちと決着の攻撃が届き、相手の画面だけが止まって試合が終わらなくなった。そこで次のように守る（`apps/web/src/game/store.ts`・`matches.gateway.ts`）。

- 画面は、届いた手を1つずつ、演出を見せてから盤面に反映する。演出1つは 12 秒まで待ち、失敗しても止まっても盤面は必ず進める（`STEP_LIMIT_MS`）。上限を過ぎたあとに演出が途中の盤面を出しても、進めた盤面は戻さない
- つなぎ直したら、見せている途中の古い手は打ち切る（古い演出が終わったあとに、届いた最新の盤面を古い盤面で上書きしない）
- 相手の手（相手の操作・時間切れ・決着）を見せ始めたら、開いている拡大・裏向きのカードの説明・確認・墓地の一覧・対戦の記録を閉じて、盤面を見せる。決着の画面は、ほかの小窓より手前に出す
- サーバーは、部屋ごとに「手を進めてから両者に送り終えるまで」を1つずつ順に行う（入り直し・時間切れ・CPU の手も同じ列）。入り直した人に送る盤面は、その列の中で読んだ最新のもの

## 手元で試す

```sh
# apps/api/.env に AUTH_DEV_LOGIN=true を足すと、名前だけでログインできる
pnpm dev
# ブラウザを2つ（片方はシークレットウィンドウ）開いて http://localhost:5173/online
```

## Google ログインの準備（本番）

（公開の全体の流れは [deploy.md](deploy.md)）

1. Google Cloud コンソール →「Google Auth Platform」→「開始」（対象は「外部」）。「対象」で「アプリを公開」して本番環境にする（使うのはメール・名前だけなので審査なし。テスト中のままだと、テストユーザーに登録した Gmail しか入れない）
2. 「クライアント」→「クライアントを作成」→ 種類は「ウェブ アプリケーション」。「承認済みの JavaScript 生成元」に Web の URL（本番は Cloud Run の URL、手元なら `http://localhost:5173`）を入れる。リダイレクト URI とクライアント シークレットは使わない
3. できたクライアント ID を API の `GOOGLE_CLIENT_ID` に入れる（Terraform の `google_client_id`）。画面は `/auth/config` から受け取るので、Web 側の設定は要らない
4. `AUTH_DEV_LOGIN` は入れない（false）。ログインの鍵（`SESSION_SECRET`）は入れなくても、アプリが初回起動時に作って DB に保存する

## 今の割り切りと、広げるとき

- 部屋の操作の順番待ち・WebSocket の部屋・ランダムマッチの待ち行列・持ち時間のタイマー・ランキングの集計は、サーバー1台のメモリにある → Cloud Run は最大1台。台数を増やすときは Socket.IO の Redis アダプターと、DB の行ロック（または楽観ロック）に替える
- フレンドは無い（オーナーの指示）。戦績の一覧は無いが、`matches` に結果（`winner_id`）とレートの動き（`ratings`）を残しているので、そこから作れる
- ランキングには Google アカウントの名前がそのまま出る

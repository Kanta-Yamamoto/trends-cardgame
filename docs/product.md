# TRENDS のプロダクトの考え方

10月24日に、オーナーの「具体的なタスクよりも、まずどう考えるべきかの整理をしたい。もうこれはプロダクト開発だろ」から作った。個々のタスク（カード・演出・機能）を決めるときの土台。オーナーの決定は日付つきで書き、まだ決まっていないものは **仮** と書く。決まったら [working-agreement.md](working-agreement.md) にも移す。

## 1. 目指す姿

オーナー：「とにかくみんなに遊んでほしい。プラットフォーマーになりたい」

| 段階 | 何になっているか |
|---|---|
| ゲーム | 友だちと遊べる、よくできたカードゲーム（いまここ） |
| 運営型のタイトル | 新しいカードと調整が定期的に届き、毎週戻ってくる理由がある |
| プラットフォーム | ネットの話題が集まる場所になる。遊ぶ人だけでなく、カードの案・大会・切り抜き動画を作る人がいて、その人たちが人を連れてくる |

プラットフォームは最初から作れない。ゲームとして遊ばれ、運営型として続いた先にある。今の判断は「遊ばれる・続く」を最優先にする。

## 2. 軸のコンセプト

### 3 つの強みと、それぞれの役目

オーナーが大事にしているものは 3 つある。どれが本当の軸か迷っているが、3 つは役目が違うので、取り合いにならない。

| 強み | 役目 | 人の動き |
|---|---|---|
| ネットミーム・話題 | 入口。知ってもらう・話題にしてもらう | 知る・広める |
| カードのデザイン・演出（立体のキラカード、攻撃モーション） | 触った瞬間の気持ちよさ。持っていたくなる | 触る・欲しくなる |
| 効果のロジック（コアファン向けの読み合い） | 続ける理由。うまくなる楽しさ | 続ける・語る |

人が「知る → 触る → 続ける → 払う → 広める」と進むとき、どこで効くかが違う。ミームは看板というより入口と世界観、演出は触ってもらう決め手と売り物、ロジックは残ってもらう理由。

### 一言にすると（仮）

**「ネットのいまが、キラカードになって戦う」**

他と違うところは、**話題になってからカードになるまでが速い**こと。AI でイラストを描き、効果はデータで書き、CPU 同士のシミュレーションで調整できるので、紙のカードゲームや大手のアプリが数か月かけるところを、数日で出せる。名前の TRENDS もここから来ている。

ただし実在の人物は描かない（[working-agreement.md](working-agreement.md)）。カードにするのは個人ではなく、**ネットの「人の型」と「現象」**（〇〇系配信者・古参・ROM専・炎上・万バズ など）。これは今のカードがすでにやっていることで、世界観の柱になる。

## 3. 誰のためか（仮）

| | どんな人 | 何に惹かれるか |
|---|---|---|
| 入口の層 | 10代後半〜20代。X・TikTok でミームを日常的に使う | 「分かる」カード。友だちに見せたくなる演出 |
| 残る層 | スマホのカードゲーム（シャドバ・ポケポケ・デュエプレ など）を遊んだことがある人・やめた人 | 短い試合での読み合い。デッキを組む楽しさ |
| 最初の 100 人 | オーナーの友人と、その友人 | 一緒に遊べること |

入口は広く（ミーム）、残すのは深く（ロジック）。どちらかに絞るのではなく、入口の層の何割かを残る層に変えるのが狙い。ここは公開後の数字で確かめる。

## 4. 判断の原則

1. **遊ばれる → 広まる → 稼ぐ の順で考える**。遊ばれていないうちに、課金や広告の作り込みをしない
2. **数字で決める**。勝率は CPU 同士のシミュレーション（今もある）と実戦の結果で、続くかどうかは継続率で見る
3. **動くもので決める**。演出はモック、ルールは CPU 戦、効果文は実際のカード面で見て決める
4. **言葉を揃える**。カード・画面・SNS・コードで同じものを同じ名前で呼ぶ（ユビキタス言語）
5. **既存のゲームを丸写ししない**。参考にするのは考え方
6. **決めたことは docs に残す**。誰が作業しても同じ判断ができるように

## 6. 段階ごとの問い

| 段階 | 期間 | 答えたい問い | 見る数字（仮） |
|---|---|---|---|
| 0. 公開前 | いま〜11/1 | 1 試合やったら、もう 1 試合やりたくなるか | 友人 1 人あたりの試合数 |
| 1. 公開直後 | 11月 | 知らない人が、次の日・次の週にも戻ってくるか | 次の日・7 日後に戻った人の割合、1 人あたりの試合数 |
| 2. 伸ばす | 継続が見えたら | どの入口（SNS・紹介・アプリストア）から人が来るか | 入口ごとの人数と、その人たちの継続 |
| 3. 稼ぐ | 伸びが見えたら | 何にお金を払うか | 払った人の割合・1 人あたりの額 |
| 4. 場になる | その先 | 遊ぶ以外の関わり方（カードの案・大会・動画）が生まれるか | 作る側の人数 |

今は、対戦の記録はオンライン対戦（`matches` の表：デッキ・勝者・時刻）にしか残らない。CPU 戦や「何人が開いて、何人が戻ってきたか」は数えていない。**段階 1 の問いに答えるには、公開の前に計測を入れる必要がある**（G の最初の一歩）。

## 7. 仕組み化

「毎回考えて作る」から「型に沿って回す」へ。Claude に任せられる工程ほど、型にすると速くなる。

| 仕組み | 流れ | 今あるもの | 足りないもの |
|---|---|---|---|
| カードを出す | 話題を拾う → 出すか決める → 効果を書く → 絵を描く → シミュレーションで調整 → 出す | 絵の注文の型（[card-art-prompt.md](card-art-prompt.md)）・総当たり（`balance.mjs`）・カード追加の手順（`CLAUDE.md`） | 話題を拾う基準と出すかの判断（D）、言葉と効果文の決まり（B） |
| 環境を動かす | 実戦の勝率を見る → 調整か新カードか決める → 出す | CPU 同士の総当たり | 実戦の勝率の集計、アップデートの周期（例：2 週ごとに新カード、月 1 で調整。仮） |
| 数字を見る | 計測 → 週 1 で見る → 次の手を決める | なし | 計測と、それを見る画面 |
| 発信する | 新カード・演出 → 短い動画 → SNS | 演出そのもの | 動画を作る型、投稿の周期 |

## 8. お金

### 課金（仮の方針）

- **勝ちを売らない。見た目を売る**。強いカードをお金で買える形は、コアファンが離れる。TRENDS の強みは演出とデザインなので、キラの加工・特別な演出・カードの姿違い・盤面など、見た目の課金と相性がいい
- カードゲームの定番はパック（ガチャ）。入れるなら、確率の表示やコンプガチャの禁止など日本の決まり、アプリストアの手数料と決済の決まり（デジタルのものはアプリ内課金が必須）を、決める前に調べる

### 広告

広告には 2 つの意味があるので分けて考える。

| | 何か | いつ |
|---|---|---|
| 載せる（稼ぐ） | アプリの中に広告を出して収入にする（見たら報酬がもらえる形など） | 段階 3 以降。遊びの気持ちよさを削るので、入れるなら報酬型に限る（仮） |
| 出す（集める） | お金を払って広告を出し、人を連れてくる | 段階 2 以降。続かないうちに出すと、お金で人を入れて逃がすだけになる。それまでは SNS・紹介で集める |

### 投資

- 今は「基本お金をかけない（友だちと試す規模）」（[working-agreement.md](working-agreement.md)）
- 外からお金を入れる（資金調達）なら、相手が見るのは段階 1〜2 の数字（継続・伸び）。だから、先に計測と公開
- 自分のお金をかけるところ（広告・イラストのツール・アプリの登録料 など）は、段階ごとに上限を決めて入れる（仮）

決まるまでは、下の仮の答えで進める。

| 問い | 仮の答え |

## 10. 直近の順番（おすすめ）

1. **言葉を揃える**（B）：ユビキタス言語と効果文の決まりを作り、今のカードを直す。公開したら文を変えにくくなるので、11/1 の前に
2. **計測を入れる**（G）：開いた人・試合数・戻ってきた人。11/1 の公開の数字を取り逃がさないために
3. **11/1 公開**：反応と数字を見る
4. **世界観の言語化**（D）：有名なカードゲームが何を絵にして、どう世界観を保っているかを調べ、TRENDS の「何をカードにするか」の決まりにする。絵の作り方（AI 感を消す）はこの後
5. **発信**（E）：公開から、新カード・演出の短い動画を出す
6. **課金・アプリ**（F・E）：継続が見えてから
